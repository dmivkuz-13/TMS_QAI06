# Требования

## 1. Общие сведения

### 1.1. Ценность вносимых изменений

**Ценность** — сокращение T2M и повышение качества предоставления услуги за счёт минимального влияния человеческого фактора.

### 1.2. Решаемые задачи (проблемы)

В текущей реализации при создании и изменении тарифа SMART настройка параметров *Архетип*, *Скидка в продаже*, *Скидка неотключаемая* осуществляется вручную. Это приводит к большому влиянию человеческого фактора на качество настроек продуктов, а также к повышенным трудозатратам. В связи с этим возникла потребность в ПО «Арена».

---

## 2. Описание запрашиваемого изменения

### 2.1. Функциональные требования

#### ФТ1

Необходимо в шаблон заявки на создание и изменение тарифов через функционал **«Шаблон / Заявка Конструктор» (Smart-флоу)** на вкладку **«Пакеты конструктора»** добавить столбцы для заполнения следующих параметров:

- **Непубличный пресет** — текстовое поле ручного ввода с допустимыми значениями:
  - `Да` = `Y` = `Отмечено` → отмечено
  - `Нет` = `N` = `Неотмечено` = `неотмечено`
- **Архетип** — текстовое поле ручного ввода для заполнения SOC. Допускаются только латинские буквы и цифры.
- **Размер для абсолютной скидки**, которая дополнительно делится на параметры:
  - **Короткий цикл** — целочисленное значение, ручной ввод (числовое редактируемое поле, обязательно для заполнения, мин. значение = 0), если заполнено поле «длинный цикл» > 0.
  - **Длинный цикл** — числовое редактируемое поле, обязательно для заполнения (мин. значение = 0), если заполнено поле «короткий цикл» > 0. При остальных значениях «Длинный цикл» всегда больше «Короткого цикла».
- **Скидки**, которая дополнительно делится на параметры:
  - **Размер % скидки** — числовое значение (может быть целым или дробным, максимально 4 знака после запятой), ручной ввод. Всегда > 0.
  - **В продаже 1С/ИМ** — возможные значения: пусто, да. Нет приравнивается к пусто.
- **Сохраняемость в пресетах** — возможные значения:
  - целые числа,
  - нет,
  - все,
  - вверх,
  - вниз,
  - пусто,
  - диапазоны через дефис.

  Допустимое заполнение: буквы кириллица (регистр не важен), цифры через запятую, диапазоны чисел через запятую, может быть несколько диапазонов в строке, пробелы игнорируются, если цифра дублируется, то не считаем за ошибку (применяем один раз). Логика применения значений описана в ФТ 4.

- **Срок действия** — целочисленное поле ручного ввода, не обязательное поле для заполнения.
- **Soc скидки** — параметр заполняется автоматически при выгрузке на изменение тарифа техническим названием созданной скидки.

Колонки разместить в указанном порядке после параметра **«Запрет продажи в 1С»**.

---

#### ФТ1.1

В рамках реализации ФТ1 на этапе выгрузки шаблона заявки для заполнения (**Шаг 1: выгрузить шаблон**) заполнение новых параметров должно происходить на следующих условиях:

- При создании тарифа — значения пустые.
- При изменении тарифа — для новых полей (ФТ1) выгружаем значения в файл. При этом данные по скидкам подтягиваем только по тем скидкам, которые положили в таблицу Х в п. 3, а именно это группы **DSC** и **GRP5**.

---

#### ФТ1.2

В рамках ФТ1 при загрузке шаблона заявки в систему реализовать проверки:

- Формат данных должен соответствовать ФТ1 — при несоответствии формата выдавать ошибку.
- Проверить значения SOC, заполненного в параметре **Архетип**, на наличие в БД (в каком-либо документе в Арене или в БД Ensemble в целом) — если такой SOC не создан, выдавать ошибку.
- При наличии пустого, не заполненного поля, на этапе создания заявки выдать предупреждение: *«Не заполнен столбец Архетип. Продолжить? Да / Нет»*.
  - **Да** — заявка создаётся.
  - **Нет** — заявка не создаётся.
- Проверить соответствие значений параметра **Непубличный пресет** — если значение отличное от перечисленных в ФТ1, выдавать ошибку.
- Не должно быть одновременного заполнения параметров **Размер % скидки** и **Размер абсолютной скидки**. Если для пресета заполнено поле с размером абсолютной скидки, то для этого же пресета не может быть заполнено поле с размером % скидки. И наоборот. При выявлении несоответствия выдавать ошибку пользователю.
- На обязательность заполнения **срока действия скидки** при заполнении значений параметров **Размер % скидки** или **Размер абсолютной скидки**.
- На обязательность заполнения поля **Короткий цикл** при заполненном значении параметра **Длинный цикл**.
- Значения параметров **«Короткий»** и **«Длинный цикл»** не равны.
- Значение параметра **«Длинный цикл»** ≥ значения **«Короткий цикл»**.
- Значение **Размер % скидки** > 0.

При выявлении хотя бы одного из перечисленных несоответствий выдавать ошибку и прерывать загрузку.

---

#### ФТ1.3

Логика обработки вносимых изменений в Заявке **«Изменение ТП Конструктор»**:

1. **Удалили скидку** (затерли данные по ней в строке) — SOC скидки необходимо удалить из соответствующей группы в Таблице Х.
2. Должна работать логика создания скидок, как при создании тарифа. Нужно в том сценарии, когда скидки изначально не планировались, но при изменении параметров появилась необходимость их создать.
3. **Добавили скидку** (заполнили пустые строки) — сгенерировать SOC скидки и прописать его в нужной группе (в зависимости от заполненных значений).
4. В столбце **«Сохраняемость в пресетах»** удалили / добавили цифру — значит, нужно удалить SOC скидки из группы DSC из удалённого номера пресета или добавить в DSC указанный номер пресета. Добавили / удалили фразу «вверх» / «вниз» — логика та же.
5. При изменении размера скидки не менять его в существующем SOC, а сгенерировать новый и прописать его по правилам выше. Старый SOC удалить из таблицы.

Можно менять **Архетип**, **Непубличный пресет**, **Нулевые пресеты**. Обработка этих изменений должна производиться по логике их создания (изменения, удаления, добавления).

#### ФТ1.4

Колонки с новыми параметрами добавить в экранные формы просмотра заявки в GUI ПО **АРЕНА**.

#### ФТ2

При создании техлиста в промежуточном окне технолога (экранная форма **«Задание параметров новых тарифов»**) на вкладке **Таблица Х** реализовать отображение всех комбинаций скидки с возможностью привязки к ним существующих SOC и выбора SOC-донора, по аналогии с опциями конструирования путём выбора из выпадающего списка.

Реализация должна представлять собой таблицу с набором полей:

- **Маркет**
- **Размер для абсолютной скидки**, которая дополнительно ��елится на параметры:
  - **Короткий цикл** — загружается из файла.
  - **Длинный цикл** — загружается из файла.
- **Скидки**, которая дополнительно делится на параметры:
  - **Размер % скидки** — загружается из файла.
- **Сохраняемая для всех пресетов** — загружается из файла.
- **Срок действия** — загружается из файла.
- **Создать новый** с возможностью настройки значения для параметров:
  - **SOC-донор** — поле с выпадающим списком с возможностью выбора существующего SOC, с которого копируются значения для скидки в продаже (цена, `def_ind`, категория), но при генерации техлиста техническое название SOC преобразуется в новое (по аналогии с опциями конструирования).
  - **Описание** — значение заполняется автоматически из БД для выбранного SOC.
- **Добавить существующий** с возможностью настройки значения для параметров:
  - **SOC** — поле с выпадающим списком с возможностью выбора существующего SOC, с которого копируются значения скидки в продаже (цена, `def_ind`, категория). При генерации техлиста техническое название SOC не меняется (по аналогии с опциями конструирования).
  - **Описание** — значение заполняется автоматически из БД для выбранного SOC.

#### ФТ2.1

В рамках ФТ2 по умолчанию, в качестве донора указать определённый SOC скидки. Их будет 2 (один для процентной скидки, второй для абсолютной, конкретные SOC сообщим чуть позже).

- Если заполнен `%`, то подставить донора для `%` скидки.
- Если заполнен размер абсолютной скидки — то подставить донора для абсолютной скидки.

Необходимо поддержать возможность изменить значение на другой SOC путём выбора из выпадающего списка.

При выборе существующего SOC перезатирается значение SOC донора в строке скидки.

**Имена SOC доноров:**
- Абсолютная скидка — `CKADONOR`
- `%` скидка — `CKXDONOR`

#### ФТ3

При создании техлиста в промежуточном окне технолога (экранная форма **«Задание параметров новых тарифов»**) необходимо добавить параметр **«Нулевые пресеты»** — чек-бокс.

Если параметр выбран, то при генерации техлиста в **Таблицу Х** добавлять в пресеты по следующей логике:

| Условие | Добавляемый SOC |
|---------|-----------------|
| Пакет минут = 0, интернет ≠ 0 | `V0LEGO` |
| Пакет интернета = 0, минуты ≠ 0 | `D0LEGO` |
| Пакет интернета = 0, минуты = 0 | `DV0LEGO` |

В любом случае: `def_ind = Y`, `АП = 0`, `категория = TECH`.

#### ФТ4

При генерации техлиста в **Таблице Х** необходимо обеспечить заполнение:

- Если значения **«В продаже 1С/ИМ»** стоит **«да»**, оба варианта скидок (`%` или абсолютная) заполнены, а в столбце **«Сохраняемость для пресетов»** стоит **Пусто**, то необходимо добавить в таблицу Х с ценами `0`, `def_ind = Y`, категория **GRP5**.
- Если заполнены поля размера абсолютной скидки или `%` скидки, но в столбце **«Сохраняемость для пресетов»** стоит **число**, то SOC скидки добавить в таблицу Х с ценами `0`, `def_ind = Y`, категория **DSC** для указанных пресетов.
- Если заполнены поля размера абсолютной скидки или `%` скидки, но в столбце **«Сохраняемость для пресетов»** стоит **«Вверх»**, то SOC скидки добавить в таблицу Х с ценами `0`, `def_ind = Y`, категория **DSC** для пресетов, у которых стоимость выше указанного пресета.
- Если заполнены поля размера абсолютной скидки или `%` скидки, но в столбце **«Сохраняемость для пресетов»** стоит **«Вниз»**, то SOC скидки добавить в таблицу Х с ценами `0`, `def_ind = Y`, категория **DSC** для пресетов, у которых стоимость ниже указанного пресета.
- Если в столбце **«Сохраняемость для пресетов»** стоит **«Да»**, то загрузку отменяем.
- Если заполнены поля размера абсолютной скидки или `%` скидки, но в столбце **«Сохраняемость для пресетов»** стоит **«Нет»**, то SOC скидки добавить в таблицу Х с ценами `0`, `def_ind = Y`, категория **GRP5** для указанных пресетов.
- Если в столбце **«Сохраняемость для пресетов»** стоит **«Все»** и **«В продаже 1С/ИМ»** стоит **«да»**, то скидку добавляем в **GRP5**, а в SOC на закладке **AMSS** необходимо проставить признак сохраняемости (`ID 200000024`).
- Для соответствующего пресета подставить строку SOC, указанного в параметре **Архетип** из заявки, со значениями параметров:
  - АП день — `0`
  - АП месяц — `0`
  - Переподключенный (`def_ind`) — `Y`
  - Группа — **TECH**
- Для соответствующего пресета, где значение параметра **Непубличный пресет** соответствует `Да = Y = Отмечено → отмечено`, подставить строку SOC (какой сообщим позже, сделать конфигурируемым по RFC) со значениями параметров:
  - АП день — `0`
  - АП месяц — `0`
  - Переподключенный (`def_ind`) — `Y`
  - Группа — **TECH**

---

#### ФТ4.1

При разнесении SOC скидки по группам всегда должно соблюдаться правило: **в рамках пресета одна скидка может находиться только в одной группе**. Первоначально определяем в **GRP5** при указании размера.

Если встречаем ситуацию, где во 2-м пресете скидка 10 % должна лежать в GRP5, но в столбце **«Сохраняемость в пресетах»** тоже стоит `2`, то мы эту `2` игнорируем (не считаем за ошибку) и SOC скидки добавляем только в GRP5 (в DSC этого пресета не прописываем).

---

#### ФТ4.2

- Если в рамках разных маркетов скидки (абсолютная или процентная) имеют одинаковый размер, и при этом по всем маркетам у них совпадает срок действия и значение, то создаём для каждого маркета свои SOC скидки.
- Если значение **«Сохраняемая для всех пресетов» = Все**, а значение параметра самой скидки и **«Срок действия»** по всем маркетам одинаковые, то в этом случае создаём общий SOC на все регионы.
- Если в рамках одного маркета прописаны скидки с одинаковым размером и сроком действия, то создаём один SOC. Например, маркет VIP, на 1-м пресете `10% - 180 дней`, и на 3-м пресете `10% - 180 дней`. В этом случае создаём один SOC скидки и кладем его в GRP5 на 1 и 3 пресете.

---

#### ФТ5

Создавать следующие маски при генерации SOC скидок:

| Маска | Описание |
|-------|----------|
| `СКA` | Имя маски для абсолютной скидки |
| `СКX` | Имя маски для `%` скидки |

Создаваемая скидка должна быть автоматически доступна в том маркет-коде, в котором обозначена в шаблоне.
